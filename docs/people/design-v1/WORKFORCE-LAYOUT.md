# Workforce: why each screen is laid out the way it is

Every surface, card and layout below has a reason taken from DESIGN.md. A new
Workforce screen picks the row that matches what it holds; it does not invent a
new arrangement.

## The four rules

| What the screen holds | How it sits | Why (DESIGN.md) |
|---|---|---|
| **A list** (people, views, pending items, org outline) | On the page ground under one hairline, rows divided by hairlines. No card around it | "A list is the page: one hairline, no wrapper" |
| **A document** (one employee record) | One white sheet per tab; sections inside it divided by hairlines, never boxed separately | "A document is a discrete object: it earns a surface"; "no card-in-card" |
| **A form being filled** (add employee, import) | One white sheet; the actions sit in its footer | The thing being made is one object, finished in one place |
| **A side task** (transfer, filters, upload, issue a letter, mark as left) | A 36rem drawer from the right, actions in its footer | The record stays in view behind it; one task, one panel |

A grouped set of figures (the metric strip) is one strip with hairlines between
the figures: one object, not five cards.

## Screen by screen

| Screen | Layout | Reason |
|---|---|---|
| Employee Directory | Page header with the one primary action (Add employee) top right; metric strip; one attention line; tabs; the table on the page ground | The list is the page. The strip is a single summary object. Alerts are one quiet line because the list, not the warning, is what the page is for |
| Pending actions, Saved views | Titled groups on the page ground, hairline rows, icon actions at the row end | Lists |
| Org Chart | Search and expand/collapse above an outline on the page ground | A list shaped as a tree |
| Documents register | Shared document list shell with its table | Same list contract as every register in the product |
| Employee record: header | Portrait, name and status, one row of facts, tags; More and Edit top right | Who this is, at a glance; one primary action |
| Employee record: Personal, Employment, Organization | One sheet; each section a titled block with a single Edit; hairlines between | One document; editing happens in place, section by section |
| Employee record: Overview | One sheet in two columns: summary sections, and recent activity behind a vertical hairline | The summary and its latest history read together, without a second card |
| Employee record: Documents | One sheet; title row with Issue a letter and Upload; file rows divided by hairlines | The person's files are part of the record |
| Employee record: History, Activity | One sheet; Activity held to a 46rem reading column | Read top to bottom; a full-width line is too long to scan |
| Add employee, Import | Step strip, then one sheet holding the step; Cancel left, Back / Save draft / Continue right in the footer | One object being built; the way forward is always in the same place |
| Drawers | 36rem, title only (no description), fields stacked, footer actions | Narrow enough to keep the record visible |

## Things deliberately not used

- No card inside a card, no separate box per section of a record.
- No page or drawer descriptions, step subtitles or help that restates a label.
- No coloured alert boxes for routine information; a dot and a line.
- No entrance animation on rows or numbers. Motion only where it explains a
  change: the tab underline moving, a panel or form appearing.
