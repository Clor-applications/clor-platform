Directory sync (SCIM 2.0)

Your identity provider adds, updates and removes people in CLOR automatically.

Accounting → Settings → Single sign-on → Directory sync. Choose the role new people get (or none, to assign later) and make a token — it is shown once.

Microsoft Entra

  1. Enterprise applications → your CLOR app → Provisioning → Automatic.
  2. Tenant URL: https://api.clor.in/scim/v2. Secret token: the one CLOR showed. Test connection.
  3. Map userName to the user's e-mail (userPrincipalName or mail), then assign users or groups and start provisioning.

Okta

Application → Provisioning → Integration: SCIM connector base URL https://api.clor.in/scim/v2, unique identifier userName, authentication HTTP header with the token. Enable Create, Update and Deactivate.

What is supported

OperationEffect in CLOR
Create userA user with that e-mail, a member of your company, with the token's role. If the e-mail already exists in CLOR they join your company instead.
Update / replaceName and e-mail follow the provider.
active = falseThe login is switched off (only for people of your account).
DeleteRemoved from your company; switched off if they had nowhere else to sign in.
GroupsNot provisioned. Roles are assigned in CLOR.

Filters supported: userName eq "…", emails eq "…". Discovery at /ServiceProviderConfig, /ResourceTypes, /Schemas.

Active Directory without a cloud identity provider: the on-site connector syncs it over the same SCIM endpoint.
